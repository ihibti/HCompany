Dark patterns detected

severity 3 obstruction step 5
“The page forces the user to engage in a chat with 'Nina from Customer Happiness' to cancel their subscription, adding an unnecessary step instead of providing a direct cancellation option. The 'Send' button is the only actionable element, requiring the user to type a message before any cancellation process can begin.”
This chat interface creates an extra step that adds friction to the cancellation process. Instead of providing a direct cancellation link or button, the user must first initiate a conversation with customer support, which is an unnecessary barrier to achieving their goal.
severity 3 sneaking step 10
“The chatbot states 'All done! I've paused your account for 3 months' after the user explicitly requested cancellation, which is a different outcome than what was requested.”
The system has already changed the account status to 'paused' instead of 'canceled' without the user's explicit consent, which is a form of sneaking the outcome.
severity 2 asymmetric choice step 10
“The 'No thanks' button is visually weaker than the 'Sure, give me 3 months free' button, which is the primary option the business wants the user to select.”
The 'No thanks' option is presented as a less prominent text link compared to the more prominent 'Sure, give me 3 months free' button, making it harder for the user to decline the offer.
severity 2 misdirection step 10
“The chatbot offers '3 months of Premium completely free' as an alternative to cancellation, with the 'Sure, give me 3 months free' button being more prominent than the 'No thanks' option.”
The design is trying to redirect the user from their cancellation goal by offering a free trial, with the 'Sure' button being more visually prominent than the 'No thanks' option.
severity 2 nagging step 8
“After the user requested cancellation, the system presented a 50% discount offer, then after the user said 'No thanks', it presented another offer for 3 months free.”
The system repeatedly presents retention offers after the user has already clearly stated they want to cancel, showing the same type of request multiple times despite the user's clear intent to cancel.
